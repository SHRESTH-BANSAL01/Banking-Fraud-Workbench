# Banking Fraud Investigation System

**A Design and Analysis of Algorithms (DAA) Project Implemented in C**

## Project Overview

The Banking Fraud Investigation System is a modular C application that demonstrates how algorithm design techniques can be applied to transaction analysis, investigation scheduling, graph optimization, resource allocation, and performance evaluation.

The system loads transaction records from a CSV dataset, calculates rule-based risk scores, identifies transactions requiring review, and demonstrates algorithms from multiple DAA paradigms.

**Note:** This is an educational prototype. It is not a production banking fraud detection system.

## Objectives

- Analyze banking transaction records.
- Identify suspicious transactions using predefined risk rules.
- Implement algorithms from different DAA paradigms.
- Optimize investigation scheduling and resource allocation.
- Compare algorithm correctness and performance.
- Generate benchmark and complexity reports.

## Algorithms Implemented

| Category | Algorithms |
|---|---|
| Divide and Conquer | Merge Sort, Quick Sort |
| Searching | Binary Search |
| Greedy | Activity Selection, Huffman Coding, Dijkstra, Prim, Kruskal |
| Dynamic Programming | 0/1 Knapsack, LCS, Matrix Chain Multiplication |
| Backtracking | N-Queens |
| Branch and Bound | 0/1 Knapsack |
| Network Flow | Edmonds–Karp, Bipartite Matching |
| Number Theory | Chinese Remainder Theorem |
| String Matching | KMP |

## Installation and Execution

Clone the repository and open the project directory.

Compile using PowerShell:

```powershell
$files = @(Get-ChildItem -Path src -Recurse -Filter *.c | ForEach-Object { $_.FullName })
gcc -std=c11 -O2 -Wall -Wextra -Iinclude $files -o fraud.exe
```

Run the complete system:

```powershell
.\fraud.exe
```

Run automated tests:

```powershell
.\fraud.exe --test
```

Run sorting benchmarks:

```powershell
.\fraud.exe --benchmark
```

Run stress tests:

```powershell
.\fraud.exe --stress
```

Compare Dynamic Programming and Branch and Bound:

```powershell
.\fraud.exe --compare
```

Generate the complexity report:

```powershell
.\fraud.exe --complexity
```

## Generated Reports

The application supports generating the following CSV files:

- `reports/sorting_benchmark.csv`
- `reports/stress_test_report.csv`
- `reports/algorithm_comparison.csv`
- `reports/complexity_report.csv`

These files are generated by their corresponding execution modes.

## Project Architecture

The project follows a modular architecture:

1. **Core Layer:** Dataset loading, transaction representation, and rule-based fraud analysis.
2. **Algorithm Layer:** Sorting, searching, greedy algorithms, dynamic programming, graph algorithms, and optimization.
3. **Testing Layer:** Automated correctness checks and stress testing.
4. **Benchmarking Layer:** Performance measurement and comparative analysis.
5. **Reporting Layer:** CSV-based algorithm performance and complexity reports.

## Limitations

- Fraud risk scores use predefined rules rather than a trained predictive model.
- Some algorithms operate on demonstration datasets instead of the imported transaction records.
- Transaction descriptions used in KMP demonstrations are hardcoded.
- Benchmarks depend on the computer, compiler, optimization settings, and input distribution.
- The system does not connect to a real banking network.
